PIVOT: Dual-View POI Semantic IDs with Vocabulary-Only Tuning for Generative Next-POI Recommendation

LLM이 POI 식별자(Semantic ID)를 직접 생성하는 생성형 추천을 연구했습니다. 기존 Semantic ID는 카테고리·지역 등 소수의 텍스트 속성만으로 만들어져, 추천에 핵심적인 POI 간 공동 방문 패턴을 담지 못합니다. 이를 모델 규모가 아닌 정보 표현 방식의 한계로 재정의하고, 텍스트와 사용자 행동 정보를 함께 쓰는 모델을 개발했습니다. 문제 정의부터 실험 설계, 구현, 3개 데이터셋 비교 실험, 논문 작성까지 전 과정을 맡았습니다.

WSDM 2027 제1저자 투고(심사 중). 한국정보과학회 2026 제1저자 게재. 한국연구재단 「석사과정생 연구장려금」 선정.

수행 내용

  • Dual-View Semantic ID — LLaMA-3.1-8B 텍스트 임베딩과 User-POI Graph에서 LightGCN으로 학습한 CF 임베딩을 각각 RQ-VAE로 양자화해, 의미 정보와 방문 패턴을 하나의 ID에 함께 표현.
  • Vocabulary-Only Tuning — SID를 문자열로 넣고 LoRA로 Backbone을 조정하는 기존 방식 대신, SID 코드를 독립 토큰으로 추가하고 Backbone은 고정한 채 SID Embedding과 Output Head의 해당 행만 학습.
  • Trajectory-wide SID Loss — 마지막 방문지에만 주던 학습 신호를 방문기록 전체 SID로 확장해 새 토큰 학습의 불안정(Collapse) 해소.
  • 평가 — NYC·TKY·CA 데이터셋에서 Graph, Sequential, LLM 기반 SOTA 5종과 비교하고, 토큰 수·CF 주입 방식을 통제한 Ablation으로 성능 향상 원인 검증.

결과

  • 3개 데이터셋 전 지표에서 SOTA 상회 — Acc@1 기준 최신 SOTA(Think2Go) 대비 최대 10.5%, SID 기반 GNPR-SID 대비 최대 17.5% 향상.
  • 프롬프트에 없는 POI 예측에서 LoRA 대비 Acc@10 최대 3.1배 — 평균 정확도로는 드러나지 않는 일반화 차이를 별도 검증.
  • LoRA 대비 학습 파라미터 4.3배 감소, 학습 GPU 메모리 41% 절감, 생성 처리량 2.2배 향상으로 학습·서빙 비용 절감.

(E-commerce) LLM 기반 생성형 Aspect-Sentiment 설명가능 추천 연구

본 연구는 (User, Item) 쌍이 주어졌을 때 사용자가 리뷰에서 언급할 Aspect-Sentiment(AS)를 예측해 설명으로 제공하는 Explainable recommender systems (ERS)을 목표로 합니다. 설명을 AS 단위로 정의하면 실제 리뷰와 직접 비교하는 객관적 정량 평가가 가능하고, Aspect별 Sentiment를 통해 설명과 평점을 하나의 근거로 연결할 수 있습니다.

연구 필요성

  • 평가 불가능한 설명 — 기존 연구(PEPLER 등)의 Free-text 설명은 BLEU·ROUGE로 평가되어 문장의 유창성만 측정하므로, 사용자의 실제 관심사를 맞혔는지 알 수 없음.
  • Cold Item과 개인화의 한계 — 리뷰가 적은 아이템은 표현이 부실하고, 인기 Aspect만으로는 사용자별 관심사를 반영하기 어려움.
  • 평점과 분리된 설명 — 평점이 보조 Loss로만 쓰여 설명이 평점의 근거가 되지 못함.

접근 방향

  • Aspect-aware Semantic ID — 아이템을 메타데이터·리뷰의 Aspect 정보를 담은 이산 코드로 표현해, 리뷰가 없는 Cold Item도 유사 아이템과 표현을 공유.
  • Aspect-aware Graph Retriever — User·Item·Aspect 그래프에서 사용자별 관심 Aspect를 Candidate로 찾아 LLM에 제공.
  • AS 기반 평점 예측 — 예측한 Aspect별 Sentiment로 최종 평점을 설명하고 예측.

실현 가능성 (예비실험)

  • AS 데이터셋 구축 — AS Extraction 모델을 Amazon 리뷰 도메인에 적응시켜 Amazon 리뷰 약 11만 건을 태깅.
  • AS 예측 — Semantic ID + Graph Retriever 기반 예비 모델이 같은 Backbone의 PEPLER 대비 F1@5 +3.2pt(32.59 → 35.78).
  • Cold Item 대응 — Graph Retriever의 정답 Aspect Recall@20이 Cold Item에서 Popularity 대비 0.685 → 0.782로 향상.
  • 설명–평점 연결 근거 — 1·2점 리뷰의 97% 이상이 NEG Sentiment를 포함하며, 정답 Aspect-Sentiment를 입력한 Upper Bound 실험에서 평점 RMSE 24% 감소(0.628 → 0.480). 현재 모델의 한계를 진단해 Sentiment 예측 강화를 다음 과제로 설정.

실시간으로 발행되는 뉴스에 맞춰 연관 OTT 컨텐츠(영화·TV)를 추천하는 그래프 기반 추천 과제입니다. 뉴스와 컨텐츠를 각각 그래프로 구성한 뒤, 공유하는 토픽 노드로 두 그래프를 잇는 뉴스-컨텐츠 통합 그래프에서 추천 후보를 찾습니다. 기업 측과의 정기 미팅에서 요구사항을 확인하며, 그래프의 구성을 위한 데이터를 실시간으로 공급하는 파이프라인을 개발했습니다.

수행 내용

  • 컨텐츠 제목 검색 개선 — 제목·유형·연도 조합으로 검색하고, 실패시 조건을 완화해 재검색하도록 구현. 원제·로마자 제목은 redirect로 처리하여 컨텐츠 검색 시스템의 정확도를 개선.
  • 컨텐츠 그래프용 메타데이터 수집·파싱 — Wikidata(감독·장르·줄거리·배우-배역)를 수집 하여, 배우-배역은 컨텐츠 그래프의 인물 노드로, 장르·줄거리는 LLM으로 처리하여 토픽 노드로 이어지도록 구현. 문서마다 다른 HTML 구조와 한국어 문서의 다양한 배우-배역 표기를 처리하는 파서를 작성했고, Wikidata에 배역 정보가 없으면 Wikipedia의 파싱 결과로 보완하도록 구현.
  • 뉴스 그래프용 실시간 수집 — 국내 9개·해외 6개 언론사의 RSS를 20분 주기로 수집하고, 기사 URL에서 본문을 크롤링해 6개 필드(제목·URL·본문·발행시각·언론사·카테고리)를 JSONL로 저장. RSS 미제공·유료 구독·피드 중단으로 수집이 불가능한 언론사는 성향이 비슷한 언론사로 대체.
  • 임베딩 기반 뉴스 중복 제거 — 여러 언론사가 같은 사건을 반복 보도하면 하나의 이슈가 여러 기사를 통해 수집되는 문제를 막기 위해, 텍스트 임베딩 기반 클러스터링을 설계 하여 실시간 중복률을 분석하여 처리.

결과

  • 하루 약 3,000건 뉴스 실시간 수집 (20분 주기 평균 42.7건, 건당 약 0.74초).
  • 시간당 유입 기사(KR 평균 138건)를 20초 이내에 처리해, 그래프 갱신 주기 안에서 실시간 중복 제거가 가능함을 확인.
  • Wikipedia 줄거리를 확보한 한국 컨텐츠 3,809건을 확보해, 컨텐츠 그래프의 토픽 할당과 뉴스-컨텐츠 연결 단계의 입력 데이터로 사용.

Improved Deep Learning Structure with Lightweight Depthwise Convolutions for Human Activity Recognition

자이로·가속도(IMU) 센서로 인간 행동을 분류하는 모델을 자원이 제한된 Edge device에서 동작하도록 경량화했습니다. 모델 개선에 그치지 않고 데이터 수집 장치 구축부터 On-device 배포·측정까지(E2E) 실험 환경 전체를 직접 만들었습니다.

HCIS(SCIE Q1) 제1저자. 2023 한국소프트웨어종합학술대회 학부생/주니어 논문경진대회 우수상.

수행 내용

  • 모델 경량화 — SOTA ResNet-SE에 Depthwise Separable Convolution을 적용해 Parameter·FLOPs를 줄이고 Overfitting 완화.
  • 데이터 수집 장치 구축 — Raspberry Pi에 IMU 센서를 I2C로 연결하고, 샘플링 주기·타임스탬프·버퍼 관리 등 수집 파이프라인을 C로 구현.
  • 사용자 실험 — 구축한 장치를 피험자에게 부착해 실환경 데이터를 수집하고 공개 데이터셋과 함께 학습·평가.
  • 온디바이스 평가 — 학습된 DL모델을 TF-Lite로 변환해 C 및 Java를 통해 Android와 Raspberry Pi에 배포, 정확도·추론시간·CPU 사용량·소비 전력 비교.

결과

  • FLOPs 73.7% 절감(42.75M → 11.26M), 파라미터 57.6% 감소(138K → 59K). 공개 데이터셋 3종(WISDM, UCI-HAR, PAMAP2)에서 SOTA, UCI-HAR 정확도 99.7%.
  • 직접 수집한 실환경 데이터 정확도 93.8% → 97.8%(F1 0.979) — 경량화가 실환경 데이터의 일반화를 높임을 실증.
  • Raspberry Pi에서 추론 시간 64.7% 단축(5.08s → 1.79s, 2.8배), 평균 소비 전력 12.1% 절감. Android에서 추론 시간 38.6% 단축(6.83s → 4.19s).
